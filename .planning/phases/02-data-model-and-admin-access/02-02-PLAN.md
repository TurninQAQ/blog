<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> login action | Untrusted email/password input enters server auth code. |
| login action -> PostgreSQL | Server creates durable admin session rows. |
| browser cookie -> server guard | Cookie token determines access to protected admin pages. |
| admin route -> browser | Protected shell must not render before server-side authorization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02-01 | Spoofing | Login action | high | mitigate | Enforce `ADMIN_EMAIL`, verify password hash server-side, and return one generic failure message for all credential failures. |
| T-02-02-02 | Information Disclosure | Login UI/action | medium | mitigate | UI and action use generic Chinese-first failure copy and do not disclose whether email or password failed. |
| T-02-02-03 | Tampering | Session cookie | high | mitigate | Store only hashed opaque tokens, use httpOnly/sameSite/secure cookie attributes, and confirm DB session expiry on every read. |
| T-02-02-04 | Elevation of Privilege | `/admin` layout | high | mitigate | `requireAdminPage()` runs on the server before rendering protected children and redirects unauthenticated requests. |
| T-02-02-05 | Repudiation | Logout/session deletion | medium | mitigate | Logout deletes the current session row and clears the cookie so stale browser state cannot retain access. |
| T-02-02-06 | Tampering | Accidental auth surface expansion | high | mitigate | Source scan blocks stock Credentials/JWT, provider login, registration, invite, reset, and Magic Link code/copy. |
</threat_model>
