# Phase 2 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 2 builds only the visible admin access boundary around the durable data/auth foundation:

- `/admin/login` email and password login.
- Server-protected `/admin` layout and landing placeholder.
- Unauthenticated redirect behavior from `/admin` to `/admin/login`.
- Login pending, invalid credential, expired-session, and guarded-shell empty/error states.
- Admin shell placeholder treatment that is consistent with the technical-lab public visual language.

Out of scope:

- Markdown editor, live preview, post list, post CRUD, taxonomy management, publish/unpublish controls, article renderer, public search, comments, multi-author UX, OAuth, Magic Link, registration, invite, public password reset, MDX/demo surfaces, and heavy public visual effects inside auth utilities.

Research caveat:

- This contract does not lock the backend auth implementation. Phase 2 research found a conflict between stock NextAuth v4 Credentials and database-backed sessions. UI implementation must target visible states only: unauthenticated login, pending login, failed login, authenticated admin shell, expired session redirect, sign out, and unauthorized mutation rejection.

Sources used:

- `.planning/REQUIREMENTS.md`: AUTH-01 through AUTH-04.
- `.planning/ROADMAP.md`: Phase 2 goal and success criteria.
- `.planning/phases/02-data-model-and-admin-access/02-CONTEXT.md`: email/password, single-admin, no reset/signup/OAuth, server redirect, shared guards, narrow admin UI scope.
- `.planning/phases/02-data-model-and-admin-access/02-RESEARCH.md`: standard stack, admin route structure, auth conflict caveat, guard/mutation boundaries.
- `.planning/phases/01-visual-foundation-and-public-shell/01-UI-SPEC.md`: existing manual Tailwind visual system.
- `src/app/globals.css`: current CSS tokens and effect safeguards.

## Layout Contract

### `/admin/login`

| Region | Contract |
|--------|----------|
| Page shell | Full viewport admin auth surface, `min-height: 100svh`, dark lab base, static grid/glow only |
| Content width | Login panel max width `400px`, centered with `16px` mobile padding and `24px` desktop padding |
| Panel | Single card, `8px` radius, secondary surface, hairline border, no nested card |
| Header copy | Compact brand lockup: `Hans' Tech Lab` plus `管理入口` |
| Form | Email input, password input, primary submit button, generic error region |
| Secondary link | One restrained text link back to `/`; no register, invite, reset, OAuth, or Magic Link links |

Login interaction:

- Email is the visible admin identifier.
- Email and password labels are visible text labels, not placeholder-only labels.
- Inputs and buttons have `44px` minimum height.
- Submit button label is `Sign in to Admin`.
- During submit, disable the button, show `Verifying access...`, and keep button dimensions stable.
- Invalid credentials show one generic error message. Do not reveal whether the email or password was wrong.
- If an expired session sends the user to login, show the expired-session copy below the form title.

### `/admin` Protected Shell

| Region | Contract |
|--------|----------|
| Server guard | Redirect unauthenticated requests to `/admin/login` before protected shell content renders |
| Admin header | Compact internal header, `56px` mobile and `64px` desktop, no public nav route strip |
| Main width | Max width `1120px`, centered, `16px` mobile padding and `24px` desktop padding |
| Landing content | One heading, one status/empty-state panel, and up to three lightweight status cards |
| Secondary action | `Sign out` control in the admin header or first status panel |

Admin landing placeholder:

- Use the protected landing only to prove admin access and show the content/auth foundation state.
- Allowed status cards: `Data model`, `Admin session`, `Mutation guards`.
- Do not render post tables, editor buttons, taxonomy chips, publish/unpublish controls, delete controls, fake articles, or placeholder CRUD actions.
- A signed-in admin should immediately understand that Phase 3 will attach the Markdown writing workflow.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline separators, focus-ring offset |
| sm | 8px | Compact element spacing, input helper gaps |
| md | 16px | Default form spacing, mobile page padding, panel padding |
| lg | 24px | Desktop page padding, panel padding, section-local gaps |
| xl | 32px | Login title/form separation, status-card grid gaps |
| 2xl | 48px | Major shell spacing, admin landing header-to-content spacing |
| 3xl | 64px | Page-level spacing on desktop |

Exceptions: `44px` minimum touch target for inputs, buttons, icon buttons, and admin header controls. Component dimensions may use `56px` and `64px` for header heights and `400px` / `1120px` max widths. Do not introduce other spacing values.

Radius:

- Inputs, buttons, chips, cards, and panels: `8px` maximum.
- Full-page shells and main page bands: no floating outer radius.
- Do not place a card inside another card.

## Typography

Use exactly these four font sizes and two weights in Phase 2.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Typography rules:

- Weights are limited to `400` and `600`.
- Letter spacing is `0`.
- Do not use viewport-width font sizing.
- Do not use Phase 1's 40px public hero display size in admin/auth surfaces.
- Login page H1 uses Display.
- Admin landing H1 uses Display on desktop and Heading on constrained mobile if needed to avoid wrapping awkwardly.
- Panel headings use Heading.
- Form labels, metadata chips, status labels, and helper text use Label.
- Body copy max width is `68ch`.
- Use `JetBrains Mono` only for short technical status labels such as `ADMIN_EMAIL`, `DATABASE_URL`, `requireAdmin()`, and mutation names. Do not use monospace for paragraphs.

## Color

|------|-------|-------|

| Secondary (30%) | `#111822` | Login panel, admin header, status panels, input backgrounds |

| Destructive | `#FF5C7A` | Destructive actions only; no visible destructive actions in Phase 2 |

Accent reserved for: login primary CTA border/glow, keyboard focus ring, authenticated session indicator, active admin shell marker, one status chip per panel, and subtle static divider/scanline treatment. Do not use accent for every link, all borders, all icons, body text, or broad background fills.

Supporting neutrals:

- Primary text: `#E8F0F8`.
- Secondary text: `#A8B3C2`.
- Muted text: `#728096`.
- Hairline border: `rgba(168, 179, 194, 0.18)`.
- Active/elevated border: `rgba(46, 242, 181, 0.32)`.

State colors:

- Error background: `rgba(255, 92, 122, 0.10)`.
- Error border: `rgba(255, 92, 122, 0.38)`.
- Error text: `#FFC1CC`.
- Disabled text: `#728096`.
- Disabled border: `rgba(168, 179, 194, 0.18)`.

Contrast rules:

- Body text on dominant or secondary surfaces must meet WCAG AA 4.5:1.
- Error text must remain readable on the error background.
- Static glow and scanline treatments must stay behind panels or on borders/dividers. They must never pass over form labels, input values, error text, or status copy.

## Interaction States

### Login Form

| State | Required Behavior |
|-------|-------------------|
| Initial | Email field is focusable first; password follows; CTA enabled only when form can submit |
| Pending | CTA disabled, dimensions stable, `Verifying access...` visible, loading icon `aria-hidden` |
| Invalid credentials | Generic Chinese-first error in a `role="alert"` region; keep email value, clear password if implementation supports it |
| Expired session | Show expired-session copy as non-error helper text above the form |
| Successful login | Redirect to `/admin`; do not show a client-only protected shell before server auth completes |
| Reduced motion | No animated scanline or hover lift; only color/opacity changes up to `80ms` |

### Protected Admin Shell

| State | Required Behavior |
|-------|-------------------|
| Unauthenticated `/admin` | Server redirect to `/admin/login`; no protected content flash |
| Authenticated `/admin` | Render admin header, signed-in status, empty-state panel, and allowed status cards |
| Session expired | Redirect to `/admin/login` and show expired-session copy if route state is available |
| Sign out | Clear session through the chosen auth stack and return to `/admin/login` |
| Guarded mutation rejected | Direct unauthenticated calls return 401/unauthorized response; no public UI should expose mutation controls |

## Accessibility Contract

Required semantics:

- `/admin/login` has one `h1`.
- The login form uses a semantic `form` with visible `label` elements for email and password.
- Email input uses `type="email"` and `autocomplete="username"`.
- Password input uses `type="password"` and `autocomplete="current-password"`.
- Error messages use `role="alert"` or an equivalent assertive live region.
- Loading status uses `aria-live="polite"` without trapping keyboard focus.
- Decorative background/effect layers are `aria-hidden="true"` and `pointer-events: none`.
- Sign-out is a button or form submit, not a fake link.

Keyboard behavior:

- All interactive elements have visible focus rings using the existing `2px` accent outline and `4px` offset.
- Tab order is brand/back link, email, password, submit, then secondary controls.
- Login errors do not steal focus unless an error summary is rendered; if so, move focus to the summary only after submit failure.
- Admin shell header controls remain reachable with keyboard and have 44px minimum target size.

Readability:

- No body text over moving effects.
- No text overlap at widths `320px`, `390px`, `768px`, `1024px`, and `1440px`.
- Long email values wrap or truncate inside protected admin status rows without widening the page.
- Admin shell cards must not shift layout when status text changes.

## Responsive Contract

| Viewport | Layout |
|----------|--------|
| 320-767px | Single-column login and admin shell, 16px page padding, full-width form controls, admin status cards stacked |
| 768-1023px | Centered login panel, admin status cards may use two columns if labels fit |
| 1024px+ | Max-width `1120px` admin shell, compact header, status cards can use up to three columns |

Mobile rules:

- Minimum tap target is `44px`.
- Login panel must fit without horizontal scrolling at `320px`.
- Error text wraps inside the panel and does not push controls off screen.
- Static background must not create horizontal overflow.

Desktop rules:

- Login panel stays compact; do not stretch it to page width.
- Admin shell surfaces remain dense and operational, not a marketing hero.
- Hover states may brighten borders or text but must not move layout.

## Visual and Motion Contract

Allowed visual motifs:

- Static dark lab grid, low-opacity scanlines, hairline borders, compact technical metadata, and restrained flowing border highlights on primary actions.

Disallowed visual motifs:

- Homepage signal canvas, pointer-follow effects, Three.js/R3F/Drei, large hero composition, public route strip, decorative gradient orb elements, bokeh blobs, nested cards, fake article thumbnails, and any visual effect imported into server auth utilities.

Motion:

- Default transitions are color, border, opacity, and shadow only, `150ms` maximum.
- Login pending spinner may rotate only when reduced motion is not requested.
- No hover lift on login form controls.
- Admin status cards may brighten border on hover/focus-within but must not translate or scale.
- Respect `prefers-reduced-motion: reduce`; transitions reduce to color/opacity changes no longer than `80ms`.
