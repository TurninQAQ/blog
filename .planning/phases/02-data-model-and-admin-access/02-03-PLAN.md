<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external caller -> admin mutation route | Untrusted direct POST calls target backend mutation URLs. |
| mutation route -> auth guard | Authorization decision must occur before input parsing or writes. |
| mutation route -> future content writes | Guard surface will protect create/edit/delete/publish/unpublish behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03-01 | Elevation of Privilege | `/api/admin/posts/[operation]` | high | mitigate | `runGuardedPostMutation()` begins by awaiting `requireAdmin()`, and the route delegates to it without reading request bodies or touching `prisma.post` directly. |
| T-02-03-02 | Tampering | Direct create/edit/delete/publish/unpublish calls | high | mitigate | Playwright direct request tests assert 401 for all five unauthenticated operations. |
| T-02-03-03 | Information Disclosure | Unauthorized responses | medium | mitigate | Responses return the generic UI-SPEC copy without operation internals or credential diagnostics. |
| T-02-03-04 | Denial of Service | Body parsing on unauthenticated requests | medium | mitigate | Guard runs before request body parsing so unauthenticated callers cannot force body-processing work. |
| T-02-03-05 | Elevation of Privilege | Accidental multi-user expansion | high | mitigate | Source review and acceptance criteria block roles, author ownership, registration, reset, OAuth, Magic Link, and stock Credentials/JWT additions. |
| T-02-03-06 | Repudiation | Authenticated mutation boundary response | low | accept | This phase proves authorization boundaries; detailed audit logs belong with real CMS writes and are not created before content mutation state exists. |
</threat_model>
