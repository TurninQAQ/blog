# Phase 04 - UI Design Contract

> Visual and interaction contract for the public content library. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 4 replaces public placeholders with real published content surfaces:

- `/notes` published article list.
- `/notes/[slug]` article detail with Markdown, code highlighting, TOC, reading time, metadata, related articles, and series navigation.
- `/tags/[slug]`, `/categories/[slug]`, `/archive`, `/series`, `/series/[slug]`, and `/search`.
- Homepage modules for real featured articles and real public statistics.
- Admin publish/unpublish/featured controls only where needed to make public visibility real.

Out of scope:

- Comments, reactions, multi-author UI, MDX demos, local media upload/storage, fake seed articles, dedicated search engine, client-side Fuse index, drag-and-drop series ordering, and heavy reading-page animation.

Sources used:

- `.planning/REQUIREMENTS.md`: READ-01 through READ-07, ORG-01 through ORG-06, SRCH-01 through SRCH-03, CMS-05, CMS-06, TAX-05, QUAL-04.
- `.planning/ROADMAP.md`: Phase 4 goal, success criteria, and plan split.
- `.planning/phases/04-public-content-library/04-CONTEXT.md`: locked Phase 4 UX and visibility decisions D-01 through D-24.
- `.planning/research/ARCHITECTURE.md` and `.planning/research/PITFALLS.md`: server-rendered public content, public query boundary, visual intensity, Markdown safety, and draft-leak pitfalls.
- Prior approved UI specs and `src/app/globals.css`: existing manual lab visual system, spacing, color, typography, radius, focus, and reduced-motion behavior.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline separators, focus-ring offset |
| sm | 8px | Metadata chip gaps, compact control gaps, list row internals |
| md | 16px | Default component spacing, mobile page padding, code block padding |
| lg | 24px | Desktop page padding, card padding, article header spacing |
| xl | 32px | Content/rail grid gap, list group spacing, search result spacing |
| 2xl | 48px | Major section breaks, article header-to-body spacing |
| 3xl | 64px | Page-level vertical spacing and wide desktop section padding |

Exceptions: `44px` minimum touch target for links, buttons, TOC rows, search submit, mobile summaries, and article action controls. Component dimensions may use existing shell widths such as `1120px`, article body widths such as `720px`, reading-shell width `840px`, and rail widths between `280px` and `320px`.

Radius:

- Cards, controls, chips, code blocks, table wrappers, empty states, and CSS visual blocks use `8px` maximum.
- Page sections are full-width bands or unframed constrained layouts, not floating section cards.
- Do not put UI cards inside other cards.

## Typography

Use exactly these four font sizes and two weights for Phase 4 public surfaces.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.1 |

Rules:

- Weights are limited to `400` and `600`.
- Letter spacing is `0`.
- Do not scale font size with viewport width.
- Public page H1 and article title use Display on desktop and may wrap naturally on mobile without shrinking below declared sizes.
- Section headings, article card titles, article Markdown `h1/h2`, and rail headings use Heading.
- Metadata, labels, tags, categories, TOC entries, dates, reading time, and code language labels use Label.
- Public article prose uses Body size with `1.65` line height inside `.lab-markdown-preview` or the public article equivalent.
- Body copy max width is `68ch`; article prose max width is `720px`.
- Code blocks and inline code use Label size in the mono font and must scroll horizontally inside the code block, never widen the page.

- Secondary text: `#A8B3C2`.
- Muted text: `#728096`.
- Hairline border: `rgba(168, 179, 194, 0.18)`.
- Active border: `rgba(46, 242, 181, 0.32)`.

Visual balance:

- Public library pages remain near-black technical lab, graphite surfaces, mint signal accent, and restrained neutral text.
- Article pages are low-intensity: no animated background or glowing overlay may pass behind prose, tables, images, or code.

## Layout Contract

### Public Library Shell

| Region | Contract |
|--------|----------|
| Max width | `1120px` for list/search/taxonomy pages, centered with `16px` mobile and `24px` desktop padding |
| Article width | Main article column max `720px`; full reading surface may reach `840px` when code/table overflow wrappers are included |
| Article rail | Desktop rail `280px-320px`, right side, sticky under header with `24px` top offset; hidden from the grid on mobile and moved into flow |
| Page header | Label eyebrow, Display H1, Body description, optional metadata row; no hero card wrapper |
| Visual intensity | List/search/taxonomy pages medium; article body low; homepage featured module may use existing glow cards |

### `/notes`

- Use an information-dense list, not a decorative card wall.
- Primary visual anchor on `/notes` is the page H1 followed by the first dense published-note row; visual blocks support scanning and must not compete with article titles.
- Each item shows title, excerpt, tags, category, publish date, reading time, and cover/technical-lab visual treatment.
- If no cover image exists, render a stable CSS technical-lab visual block with grid/trace treatment and `8px` radius.
- Desktop may use a two-column rhythm only if excerpts and metadata remain scannable; default recommendation is a single-column dense list with optional thumbnail/visual block.
- Mobile stacks visual block, title, excerpt, metadata, and tags in that order.

### Article Detail

- Use a server-rendered article route at `/notes/[slug]`.
- Draft, archived, unpublished, and nonexistent slugs render the same 404 behavior and must not reveal hidden content.
- Desktop layout: article column left, right rail containing TOC above related articles.
- Mobile layout: article header, folded/mobile TOC before the body, article body, series navigation, related articles.
- Main reading surface must not have continuous animation.
- Article links, heading anchors, TOC links, and related/series links use visible focus rings and stable dimensions.
- Metadata row includes category, publish date, reading time, and tags. It must wrap without overlapping the title or rail.

### Taxonomy, Archive, and Series

- `/tags/[slug]` and `/categories/[slug]` use independent semantic routes and list only published posts.
- `/archive` groups posts by year and month. Year headings use Heading; month rows use Label plus article list items.
- `/series` entry page shows only series name and description. Do not show per-series post counts or latest-update metadata.
- `/series/[slug]` orders posts by `seriesOrder` ascending and uses visible order numbers or step markers.
- Article detail shows previous/next series navigation when the current article belongs to a series.

### Search

- `/search` uses a GET-query search form with a visible label and stable submit button.
- Results show title, excerpt, publish date, category, tags, and reading time.
- Search must never show drafts or unpublished posts.
- Do not build a client-side Fuse index or dedicated search UI in Phase 4.

### Homepage Modules

- Replace placeholder modules with real featured articles and real statistics.
- Featured articles require an explicit `featured` data field; do not infer featured status from latest publish time.
- If no featured articles exist, show the generic polished empty state; do not generate fake posts.

## Interaction Contracts

### Article Reading

- TOC links jump to generated heading ids with `scroll-mt-24` or equivalent offset so the sticky header does not cover headings.
- Desktop TOC remains sticky; mobile TOC is folded into flow before the article body and must not squeeze prose.
- Related articles appear below TOC on desktop and after article/series navigation on mobile.
- Code blocks and tables scroll internally on the x-axis. Page-level horizontal overflow is a failure.
- External Markdown links open in a new tab with `rel="noreferrer"`; internal links stay in the same tab.

### Publish Visibility

- Publish sets `publishedAt` only on first transition to `PUBLISHED`.
- Editing an already-published article updates public content immediately.
- Unpublish returns the post to draft and removes it from every public surface.
- Unpublish requires confirmation copy from the Copywriting Contract.
- Publish action copy: `发布文章`.
- Unpublish action copy: `取消发布`.
- Featured toggle copy: `设为精选` / `取消精选`.

### Search

- Empty query state shows no results list and uses the no-query copy.
- While searching, keep input and submit dimensions stable.
- Search results are regular links to article pages with clear focus rings.
- No result state does not expose unpublished/draft existence.

### Empty, Error, and 404 States

- Public empty states use `PublicEmptyState` with page-specific Chinese copy.
- Public error states use the generic error copy and provide one non-primary link back to `/`.
- 404 for article slugs uses the same treatment for nonexistent and unpublished posts.
- No empty state may link to `/admin`, mention drafts, or tell visitors how to publish content.

### Motion

- Article detail pages allow only static grid/glow, hover border changes, focus rings, and short color/opacity transitions.
- No continuous animation behind article prose, code, tables, TOC, or related cards.
- Card hover may use existing `lab-glow-card` behavior on lists, but hover lift remains `2px` maximum and is disabled by reduced-motion.
- Reduced motion disables scanlines, hover lift, pointer-follow, and any nonessential animation; color/opacity transitions are limited to `80ms`.

## Accessibility Contract

- Each public page has exactly one `h1`.
- Article detail uses semantic `article`, article header, and `nav aria-label="目录"` for TOC.
- Related articles use a labelled section; series previous/next uses labelled navigation.
- Search uses a visible `label`, real form submit, and keyboard-reachable results.
- All interactive elements meet `44px` minimum touch target where practical.
- Focus ring is `2px` accent outline with `4px` offset.
- Decorative visual blocks and background effects are `aria-hidden` unless they are meaningful cover images with alt text.
- Article cover images use the article title or empty alt depending on whether the image adds information; CSS visual fallback is decorative.
- Mobile TOC folding uses a native `details/summary` or equivalent accessible disclosure.
- Tables retain header semantics and get an internal scroll wrapper.
- Long words, URLs, code, tags, and Chinese/English mixed titles must wrap or scroll inside their own container without overlapping adjacent content.

## Responsive Contract

| Viewport | Layout |
|----------|--------|
| `320px-767px` | Single column, `16px` page padding, mobile TOC in flow, related/series after article body, no rail, no pointer-follow effects |
| `768px-1023px` | Single article column or rail moved below article if width is tight; list cards may use two columns only if metadata wraps cleanly |
| `1024px+` | `1120px` public layout, article plus right rail, sticky TOC above related articles, dense lists remain scannable |

Verification targets: `320px`, `390px`, `768px`, `1024px`, and `1440px`. No public content surface may have incoherent overlap, clipped button text, or page-level horizontal overflow.
