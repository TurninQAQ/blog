## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local admin/test data -> screenshots | Temporary protected content becomes persistent binary evidence. |
| screenshot filesystem -> evidence manifest | File freshness and integrity claims are derived from mutable local files. |
| visual observation -> release gate | Human layout/motion judgments become structured pass/fail evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-04-01 | Information Disclosure | screenshots | high | mitigate | Use a generated fixture, inspect each retained image, and delete the fixture before acceptance. |
| T-05-04-02 | Tampering | evidence manifest | high | mitigate | Record per-file SHA-256, mtime, captured_at, and session-start freshness; recompute in verification. |
| T-05-04-03 | Repudiation | visual matrix | medium | mitigate | Require explicit route/viewport/motion/result/finding rows and preserve failures as blockers. |
| T-05-04-04 | Denial of Service | release fixture | low | mitigate | Use one bounded fixture and clean it through existing admin operations after capture. |
| T-05-SC | Tampering | npm installs | high | mitigate | No package installation or dependency change is authorized in this plan. |
</threat_model>
