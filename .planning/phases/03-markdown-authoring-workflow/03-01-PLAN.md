**As a** site owner, **I want to** create, edit, list, save, and delete draft technical notes in the protected admin backend, **so that** the Markdown authoring workflow has a real database-backed writing loop before editor and taxonomy polish are added.

<objective>
Build the vertical draft-management slice for Phase 3: protected dashboard, draft list, draft editor shell, guarded create/edit/delete API behavior, draft validation, slug generation, duplicate slug handling, and hard delete confirmation.

Purpose: This turns the Phase 2 protected admin placeholder into a real draft CMS path while preserving the guard-first mutation boundary.
Output: Admin dashboard/list/editor routes, server-only post query and mutation helpers, zod input schemas, hard delete dialog, and Playwright coverage for minimal draft CRUD.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external caller -> admin post API | Untrusted callers can post arbitrary JSON to mutation URLs. |
| protected admin UI -> guarded dispatcher | Browser form state is untrusted until authenticated and validated server-side. |
| mutation dispatcher -> PostgreSQL | Validated draft data creates, updates, or deletes durable post rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01-01 | Elevation of Privilege | `runGuardedPostMutation()` | high | mitigate | Preserve `requireAdmin()` as first executable statement and keep source-order tests from `admin-mutations.spec.ts`. |
| T-03-01-02 | Tampering | Draft create/edit JSON | high | mitigate | zod schemas validate required title/body, slug format, ids, cover URL, and draft-only status after authorization. |
| T-03-01-03 | Tampering | Duplicate slugs | medium | mitigate | Validate slug uniqueness before write and catch Prisma unique conflicts with the duplicate slug copy. |
| T-03-01-04 | Tampering | Hard delete | high | mitigate | UI requires explicit title-bearing confirmation; backend delete remains admin-guarded. |
| T-03-01-05 | Information Disclosure | Unauthorized errors | medium | mitigate | Preserve generic unauthorized copy and avoid returning draft details before auth. |
| T-03-01-06 | Elevation of Privilege | Publish scope creep | high | mitigate | No publish button or public visibility mutation is added in Phase 3; publish/unpublish remain guarded compatibility only. |
</threat_model>
