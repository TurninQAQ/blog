# Phase 1 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 1 builds the actual public shell and homepage experience for a programmer-focused personal technical lab blog. It must establish the visual system, app shell, homepage identity, route placeholders, and immersive effect foundation that later content/admin phases reuse.

This phase is not a marketing placeholder. The first screen must be usable as the public entry point: visitors should immediately understand the site owner's programmer identity and have obvious routes into notes, series, archive, and search placeholders.

Out of scope for this phase:
- Real article data, article detail rendering, tags/categories/series data, archive data, and search results.
- Admin authentication, admin layout, editor, and publishing workflows.
- Three.js or React Three Fiber unless a later phase explicitly proves that CSS plus 2D Canvas cannot deliver the desired effect.

Sources used:
- `.planning/PROJECT.md`: technical-lab direction, immersive effects, homepage personal profile, Markdown notes.
- `.planning/REQUIREMENTS.md`: VIS-01 through VIS-05, QUAL-02, QUAL-03.
- `.planning/ROADMAP.md`: Phase 1 goal, success criteria, and three planned implementation slices.
- `.planning/research/STACK.md`: Next.js, Tailwind CSS v4, Motion, optional Three.js, lucide-react.
- `.planning/research/PITFALLS.md`: visual intensity levels, reduced-motion, mobile performance, hydration safety.

## Layout Contract

### Public Shell

| Region | Contract |
|--------|----------|
| Root background | `min-height: 100svh`, dominant near-black surface, fixed ambient layer behind content, no horizontal overflow |
| Content max width | `1120px` for shell sections, centered with `16px` mobile padding and `24px` desktop padding |
| Header | Sticky top header, `56px` mobile height, `64px` desktop height, translucent secondary surface with blur fallback |
| Main | Relative stacking context above background effects, no content depends on effect hydration |
| Footer | Compact technical metadata footer with links to notes, series, archive, search, and source/profile link placeholder |

Header behavior:
- Desktop `>= 768px`: logo left, nav links right, primary route button `Explore Notes`.
- Mobile `< 768px`: logo left, `Menu` icon button right, full-height menu panel with 44px minimum tap targets.
- Header must remain readable when the animated background is unavailable.
- Header blur must have an opaque fallback color for browsers/devices where backdrop filter is disabled.

Homepage first viewport:
- Use a full-bleed technical-lab scene as the background, with hero copy over it directly, not inside a card.
- Hero minimum height: `calc(100svh - 64px)` on desktop and `calc(100svh - 56px)` on mobile.
- Hero content block max width: `720px`.
- Keep the bottom of the next section visible or hinted on common desktop and mobile viewports by placing a route strip or section teaser immediately after the hero and using a downward fade/edge, not by making the hero taller than the viewport.
- Do not use a split hero where text is on one side and a decorative card/image is on the other.

Homepage section order:
1. Hero identity: brand/name signal, concise programmer profile, primary and secondary route actions.
2. Content route strip: notes, series, archive, search placeholders as real navigable routes or scaffolded links.
3. Featured notes preview: 3 placeholder technical-note cards with clear empty-state handling until data exists.
4. Article reading surface preview: a static placeholder that demonstrates prose width, code-block treatment, and visual intensity reduction for reading.
5. Footer.

Route placeholder contract:
- `/notes`, `/series`, `/archive`, and `/search` may be placeholder pages in Phase 1, but each must render inside the same public shell.
- Placeholder pages must use the empty-state copy in this spec and must not show broken links, fake loading spinners, or dead controls.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline separators, focus-ring offset |
| sm | 8px | Compact element spacing, badge padding, icon/text gaps |
| md | 16px | Default element spacing, mobile page padding, card internal padding |
| lg | 24px | Desktop page padding, section-local gaps, hero action gaps |
| xl | 32px | Grid gaps, card group spacing, section header spacing |
| 2xl | 48px | Major section breaks, hero copy vertical rhythm |
| 3xl | 64px | Page-level section padding, desktop hero/header spacing |

Exceptions: `44px` minimum touch target for icon buttons, nav rows, and primary/secondary actions. Do not introduce other spacing values unless they are component dimensions such as header height or canvas bounds.

Radius:
- Buttons, chips, inputs, and cards: `8px` maximum.
- Full-screen/mobile menu panel: `0px` outer radius.
- Effect masks and glows may use circular/radial gradients, but not decorative orb elements.

## Typography

Use exactly these four font sizes and two weights in Phase 1.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.1 |

Typography rules:
- Weights are limited to `400` and `600`.
- Letter spacing is `0`.
- Do not use viewport-width font sizing.
- Hero display text must wrap naturally on mobile. Do not shrink text below the declared sizes with viewport math.
- Body copy max width is `68ch`.
- Reading preview width is `720px` max for prose and `840px` max when a code block is included.
- Use `JetBrains Mono` only for code previews, short route metadata, command-like labels, and technical counters. Do not use monospace for long prose.

Required homepage copy scale:
- Brand/eyebrow: Label.
- Hero H1: Display.
- Hero support copy: Body.
- Section headings: Heading.
- Cards, route labels, metadata: Label or Body only.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#070A0F` | Page background, article-safe surfaces, effect fallback base |
| Secondary (30%) | `#111822` | Header, cards, route panels, placeholder surfaces, footer |
| Accent (10%) | `#2EF2B5` | Primary CTA, active nav marker, focus ring, selected route state, hero scanline, key metadata chips |
| Destructive | `#FF5C7A` | Destructive actions only; no destructive actions are in Phase 1 |

Accent reserved for: primary CTA border/glow, active nav indicator, keyboard focus ring, selected route chips, hero scanline/light-flow strokes, and the most important metadata chip on a card. Do not use accent for all links, all borders, body text, or decorative fill across the page.

Supporting neutrals:
- Primary text: `#E8F0F8`.
- Secondary text: `#A8B3C2`.
- Muted text: `#728096`.
- Hairline border: `rgba(168, 179, 194, 0.18)`.
- Elevated border: `rgba(46, 242, 181, 0.32)` only on active/featured items.

Contrast rules:
- Body text on dominant or secondary surfaces must meet WCAG AA 4.5:1.
- Accent text must not be used on light/glowing backgrounds unless contrast is checked.
- Flowing light effects must stay behind content or on borders/dividers. They must never pass over body copy or code text.

Visual balance:
- The page should read as near-black technical lab, graphite surfaces, mint signal accent, and small neutral text variation.
- Avoid a one-hue blue/slate-only result. Use the mint accent and subtle neutral contrast to keep the page from becoming a flat dark-blue UI.

## Visual Language

The public shell should feel like a technical lab, not a SaaS dashboard and not a generic landing page.

Allowed visual motifs:
- Fine grid lines, low-opacity coordinate marks, scanlines, waveform/trace paths, terminal-like metadata, and flowing border light.
- Subtle mouse-following light field on desktop only.
- Particle or signal-node motion in the hero background using 2D Canvas.
- Code/prose preview surfaces that hint at technical notes without pretending real posts exist.

Disallowed visual motifs:
- Gradient orb decorations, bokeh blobs, beige/cream themes, stock photos, generic abstract SVG hero art, and nested cards.
- Always-on heavy WebGL.
- Text placed directly over high-motion or high-contrast particle areas without a stable overlay/mask.

Visual intensity levels:
- Homepage hero: high intensity allowed behind content, with masks ensuring text readability.
- Homepage sections and list placeholders: medium intensity with static grid and border glow only.
- Article/reading preview and later article pages: low intensity; no moving background behind prose.

## Motion and Effect Contract

Phase 1 effect choice: CSS plus 2D Canvas plus Motion. Do not add Three.js or React Three Fiber in this phase.

Layering:
1. Static CSS base: radial depth gradients, grid texture, and scanline overlay. This renders before JavaScript.
2. Optional 2D Canvas hero layer: particles, flowing trace lines, or signal nodes. It is client-only, dynamically loaded, `aria-hidden`, and `pointer-events: none`.
3. UI motion: Motion or CSS transitions for nav/menu/card interactions only.

Performance limits:
- Canvas only on homepage hero.
- Canvas device pixel ratio cap: `1` on mobile, `1.5` on desktop.
- Particle/signal count cap: `36` mobile, `72` tablet, `120` desktop.
- Pause canvas animation when document is hidden or when the canvas is outside the viewport.
- Do not import animation/effect code into placeholder route pages unless they render the homepage hero.
- No Motion-driven layout animations that resize text containers.

Interaction behavior:
- Desktop pointer movement may influence a light field or signal attractor with eased movement.
- Mobile uses no pointer-following behavior.
- Card hover may reveal a border trace and slight lift of `2px`; no scale above `1.01`.
- Primary CTA hover may brighten border/glow. Text position must not shift.
- Mobile menu opens and closes with opacity/translate transition no longer than `180ms`.

Reduced-motion behavior:
- Respect `prefers-reduced-motion: reduce`.
- Disable canvas animation, parallax, pointer-follow, hover lift, and looping scanline motion.
- Keep a static grid/trace background with no animated position changes.
- Transitions in reduced motion are limited to color/opacity changes no longer than `80ms`.

Hydration fallback:
- The homepage must be readable and visually coherent before the Canvas layer hydrates.
- If Canvas fails, the static CSS background remains; no blank white/black rectangle should appear.
- Effect components must not reserve layout height. They are positioned behind content.

## Accessibility Contract

Required semantics:
- One `h1` on the homepage.
- Header uses `header`, navigation uses `nav`, main content uses `main`, footer uses `footer`.
- Canvas/effect layers are `aria-hidden="true"` and not focusable.
- Mobile menu trigger exposes expanded state and an accessible label.

Keyboard behavior:
- All interactive elements have visible focus rings using accent color.
- Focus ring: `2px` accent outline with `4px` offset.
- Mobile menu closes on Escape and returns focus to the trigger.
- Route cards that are links must be single focus targets, not nested interactive elements.

Readability:
- No body text over moving effects.
- No text overlap at widths `320px`, `390px`, `768px`, `1024px`, and `1440px`.
- Long route/card labels wrap cleanly within their containers.
- Code preview lines can horizontally scroll inside the code block; they must not widen the page.

## Responsive Contract

| Viewport | Layout |
|----------|--------|
| 320-767px | Single-column homepage, 16px page padding, mobile menu, hero content starts near top third, no pointer-follow effect |
| 768-1023px | Two-column card grids allowed, desktop/tablet nav visible if labels fit, reduced particle count |
| 1024px+ | Full desktop header, max-width 1120px sections, route strip can use 4 columns, hero content max 720px |

Mobile rules:
- Minimum tap target is `44px`.
- Header and menu must not cover focused content when opened.
- Hero H1 wraps to multiple lines without clipping.
- Visual effects must not create horizontal overflow.
- Background Canvas may render fewer particles, but content hierarchy must remain the same.

Desktop rules:
- Pointer-follow effect must feel ambient, not like a cursor replacement.
- Hover/focus states must be visible but restrained.
- Wide screens keep content centered; do not stretch prose/cards beyond the max widths.
